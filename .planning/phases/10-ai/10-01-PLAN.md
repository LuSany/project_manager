  <files>src/app/api/v1/ai/scan/risk/route.ts, src/lib/ai-reviewer.ts, src/app/api/v1/reviews/[id]/ai-vote/route.ts, src/app/api/v1/reviews/[id]/resolution-draft/route.ts</files>

1. **创建 AI 评审员核心库** — `src/lib/ai-reviewer.ts`:
   - `addAIReviewer(reviewId: string)` — 将系统 AI 用户添加为 AI_REVIEWER 参与者到 review_participants
   - `submitAIVote(reviewId: string, agreed: boolean)` — 使用系统 AI 用户 ID 提交投票到 review_votes
   - `generateResolutionDraft(reviewId: string, userId?: string)` — 调用 ai-review.ts 的 `generateSummary()` 生成决议草案，返回 Markdown 格式（包含结论、关键发现、建议行动，per D-13）

关键：系统 AI 用户 ID 为 `'system-ai-reviewer'`，在 review_participants 和 review_votes 中使用。

2. **创建定时风险扫描 API** — `src/app/api/v1/ai/scan/risk/route.ts`:
   - POST 端点，接受 `{ projectIds: string[] }` 参数
   - 对每个项目调用 `analyzeRisk()` 获取分析结果
   - 将分析结果存入 `ai_response_cache`（key: `ai-risk-scan:{projectId}:{date}`）
   - 通过 `notifyAIRiskScanResult()` 向项目负责人发送通知（per D-10, D-11）
   - 不自动创建风险记录，仅通知用户查看（per D-10）
   - 返回 `{ success: true, scannedProjects: number, totalRisks: number }`
   - 权限检查：仅 ADMIN 或系统调用可用（通过检查 API key header 或内部 token）

3. **创建 AI 投票端点** — `src/app/api/v1/reviews/[id]/ai-vote/route.ts`:
   - POST 端点，触发 AI 评审员投票
   - 获取评审材料和参与者的投票状态
   - 调用 `callAI()` 分析材料并生成投票建议（agreed/disagreed）
   - 通过 `submitAIVote()` 记录投票
   - 标记投票为 AI 生成（可在 review_votes 中添加注释或利用 AI_REVIEWER 角色区分）
   - 权限：系统内部调用，验证 review 存在且状态为 IN_PROGRESS

4. **创建决议草案端点** — `src/app/api/v1/reviews/[id]/resolution-draft/route.ts`:
   - POST 端点，生成评审决议草案（per AIREV-04, D-13）
   - 调用 `generateResolutionDraft()` 获取 AI 生成的摘要
   - 将结果格式化为 Markdown：标题（评审标题 + "决议草案"）、结论、关键发现（keyPoints 列表）、建议行动（conclusion）
   - 缓存结果到 `review_ai_analysis`（analysisType: 'RESOLUTION_DRAFT'）
   - 返回 `{ success: true, draft: { markdown: string, generatedAt: string } }`

5. **注意**：所有 API 端点遵循项目现有模式：`NextRequest` → Zod 验证 → `getAuthenticatedUser` → 业务逻辑 → `ApiResponder.success/error` 响应。
