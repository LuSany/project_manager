# Feature Landscape

**Domain:** 现代化项目管理 UI
**Researched:** 2026-03-25

## Table Stakes

基础功能：用户期望的核心功能，缺失则产品显得不完整。

| 功能 | 为什么需要 | 复杂度 | 备注 |
|------|------------|--------|------|
| **多视图任务管理** - 列表/看板/日历切换 | 不同工作场景需要不同视图：列表用于批量操作、看板用于流程管理、日历用于时间规划 | 中 | 参考 Plane/Vikunja，需支持视图间无缝切换 |
| **甘特图/时间线视图** | 项目规划、依赖关系可视化、关键路径分析的基础工具 | 高 | 现有数据库支持任务依赖，需自定义 SVG 或集成专业库 |
| **可折叠侧边栏导航** | 现代 SaaS 标准布局，最大化内容区域同时保持导航可达 | 低 | 参考 Plane 深色模式命令面板风格 |
| **命令面板 (Cmd+K)** | 快速导航和操作的行业标准，提升高级用户效率 | 中 | 需集成搜索、导航、快捷操作 |
| **仪表盘与统计卡片** | 项目健康状况一目了然：进度、风险、任务完成率 | 中 | 需支持自定义时间范围和数据筛选 |
| **深色/浅色主题切换** | 开发者期望的标配功能，影响产品"现代感" | 低 | shadcn/ui 原生支持 |
| **通知中心** | 任务分配、评审请求、风险预警的即时触达 | 中 | 已有基础设施，需优化 UI 呈现 |
| **文件上传与预览** | 评审材料、项目文档的基础载体 | 中 | OnlyOffice 集成已存在 |
| **移动端响应式** | 非原生 App 但需保证手机端基本可用 | 中 | Tailwind CSS 4 支持良好 |
| **设备预定时间选择器** | 设备管理的核心交互，需直观展示可用时段 | 中 | 参考会议室预定系统交互模式 |
| **审批流程 UI** | 设备预定、需求变更等场景需要审批流可视化 | 中 | 需展示审批链、当前状态、历史轨迹 |
| **评审投票界面** | 评审流程的核心交互，需清晰展示选项和结果 | 中 | 支持匿名/实名、权重配置 |

## Differentiators

差异化功能：不是用户预期的标配，但能形成竞争优势。

| 功能 | 价值主张 | 复杂度 | 备注 |
|------|----------|--------|------|
| **AI 风险自动识别** | AI 分析项目数据主动发现潜在风险，而非被动记录 | 高 | 核心竞争力：从"记录工具"升级为"决策助手" |
| **AI 风险评级建议** | AI 评估概率和影响程度，减少主观偏差 | 高 | 需展示 AI 判断依据，建立用户信任 |
| **AI 应对方案生成** | 基于风险类型自动生成应对策略建议 | 高 | 可结合历史项目数据训练 |
| **AI 评审员角色** | AI 作为独立评审参与者提供客观意见 | 高 | 差异化亮点：24/7 可用的"专家"评审员 |
| **评审材料 AI 分析** | 自动提取文档关键信息、发现矛盾和遗漏 | 高 | 大幅减少人工审阅时间 |
| **AI 问题自动识别** | AI 发现评审材料中的技术/逻辑问题 | 高 | 需支持多格式文档 (PDF/Word/代码) |
| **AI 决议草案生成** | 评审结束后自动生成结构化结论文档 | 中 | 整合讨论要点和投票结果 |
| **设备使用率分析报表** | 可视化展示设备利用率、项目机时分布 | 中 | 帮助优化资源配置决策 |
| **配额管理与预警** | 设备使用配额超限前主动提醒 | 低 | 避免资源争用冲突 |
| **定期风险扫描** | 定时任务自动扫描项目数据生成风险报告 | 中 | 变被动为主动的风险管理 |
| **活动热图** | GitHub 风格贡献热图展示团队活跃度 | 低 | 直观呈现团队工作模式 |
| **里程碑进度可视化** | 燃尽图/里程碑进度条展示项目健康度 | 中 | 参考 Vikunja 仪表盘设计 |

## Anti-Features

刻意不构建的功能：避免范围蔓延和资源浪费。

| 反功能 | 为什么避免 | 替代方案 |
|--------|------------|----------|
| **移动端原生 App** | 开发维护成本极高，用户使用频率不足以证明投入 | 做好 Web 响应式，优先保证桌面端体验 |
| **实时协作编辑** | 技术复杂度高 (OT/CRDT 算法)，非核心场景 | 乐观更新 + 定期刷新足够满足需求 |
| **视频会议集成** | 与腾讯会议/Zoom 等平台重复建设，API 集成维护成本高 | 提供会议链接字段，外部工具完成 |
| **即时通讯/聊天** | Slack/钉钉/飞书已解决，垂直整合价值低 | 通知系统集成 Webhook 推送至 IM 工具 |
| **代码托管功能** | GitHub/GitLab 是专业领域，重复建设无意义 | 通过 Webhook 关联代码提交和任务 |
| **复杂报表自定义** | 学习曲线陡峭，大多数用户不会使用 | 提供 5-8 个精心设计的预设报表 |
| **拖拽甘特图编辑** | 技术复杂度极高，与列表编辑体验不一致 | 甘特图主要用于查看，编辑用列表/详情 |
| **多语言国际化** | 当前用户群体以中文为主，可后期扩展 | 代码层面预留 i18n 接口，暂不实现 |

## Feature Dependencies

```
设备预定 UI → 设备管理 CRUD (先有设备才能预定)
设备预定 UI → 冲突检测算法 (后端支撑)
审批流程 UI → 细粒度权限模型 (现有数据库已支持)

甘特图视图 → 任务依赖关系 (现有数据库已支持)
甘特图视图 → 任务时间字段 (startDate/endDate)

AI 风险识别 → 风险数据结构 (现有 Risk 模型)
AI 风险识别 → AI 配置 (现有 Admin 配置支持)

AI 评审员 → 评审流程数据结构 (现有 Review 模型)
AI 评审员 → 文件解析能力 (依赖 OnlyOffice 集成)
AI 决议草案生成 → AI 评审员投票结果

仪表盘 → 项目/任务/风险统计数据
仪表盘 → 活动日志 (现有 Audit 模型)

命令面板 → 全局搜索索引
命令面板 → 路由系统 (Next.js App Router)
```

## MVP Recommendation

**Phase 1: UI 现代化核心 (优先构建)**

1. **可折叠侧边栏 + 主题切换** - 基础设施，影响整体视觉感受
2. **命令面板 (Cmd+K)** - 现代 SaaS 标配，提升产品质感
3. **列表视图/看板视图切换** - 最常用视图，日历视图可延后
4. **仪表盘统计卡片** - 项目健康度快速感知
5. **深色模式完整支持** - 开发者偏好强烈

**Phase 2: 设备管理 MVP**

1. **设备 CRUD 界面** - 基础数据管理
2. **时间选择器 + 可用时段展示** - 预定核心交互
3. **简单冲突检测提示** - 避免重复预定
4. **我的预定列表** - 用户查看自己的预定

**Phase 3: AI 增强 MVP**

1. **AI 风险识别 (手动触发)** - 先支持手动分析，验证效果
2. **AI 评审材料摘要** - 单一高价值功能，减少审阅时间
3. **风险评级建议展示** - 辅助决策，最终决定权在人

**延后构建:**
- 日历视图：依赖关系复杂，Phase 1 后可用列表/看板满足基本需求
- 甘特图：技术复杂度高，Phase 1 用简单时间线替代
- AI 决议草案生成：需要完整评审流程数据积累
- 设备使用率报表：管理功能，可延后于预定核心流程
- 定期风险扫描：需要先验证手动分析效果

## 功能复杂度评估汇总

| 复杂度 | 功能数量 | 典型功能 |
|--------|----------|----------|
| **低** | 5 | 主题切换、配额预警、活动热图 |
| **中** | 12 | 命令面板、仪表盘、审批流程、预定时间选择器 |
| **高** | 8 | 甘特图、AI 风险识别、AI 评审员、评审材料分析 |
